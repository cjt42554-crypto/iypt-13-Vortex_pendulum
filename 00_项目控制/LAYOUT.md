# 仓库布局

```text
README.md
AGENTS.md
00_项目控制/
01_最终理论/
02_模拟程序/
03_项目资料/
90_候选工作区/
├── current/
└── archive/
tools/
.github/workflows/
```

## 目录职责

| 路径 | 职责 |
|---|---|
| `00_项目控制/` | 单一状态源、布局和工作流 |
| `01_最终理论/` | 已接受的理论成熟基线 |
| `02_模拟程序/` | 已接受的程序成熟基线 |
| `03_项目资料/` | 已接受的资料、协议、结果和归档 |
| `90_候选工作区/current/` | 当前候选、管理记录和审查材料 |
| `90_候选工作区/archive/` | 被替代候选归档 |

`01_最终理论` 的路径名为兼容既有研究资料而保留；其语义是当前成熟理论基线，不是不可修改的最终真理。

## 状态单一化

- 动态状态只写入 `STATUS.md`。
- 根 README 只导航。
- 当前候选 README 只描述候选自身。
- 历史审查和冻结证据保留生成时路径，不作为活动入口。

三个成熟目录的内部 tree 是受保护结构；任何调整都必须按成熟基线回写规则记录和验证。当前目录、入口和链接约束由 `tools/check_repository_layout.py` 检查。
