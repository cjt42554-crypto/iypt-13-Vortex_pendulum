# 工作、验证与晋升规则

## 1. 每次任务开始

1. 完整阅读根 `AGENTS.md`、本目录全部文件和当前任务入口。
2. 只读核对仓库根目录、远端、默认分支、当前分支、HEAD 和工作区。
3. 检查是否存在未提交、未跟踪或来自其他人的修改。
4. 比较交接状态与实时 Git；有漂移先报告，不覆盖。
5. 确认本轮目标、允许路径、禁止路径和停止条件。

## 2. 普通工作任务

- 默认只在 `未提交修改` 中工作。
- 理论、代码、测试、配置、审查和验证在同一个候选身份下演进。
- 候选文件将来若要进入成熟目录，必须在 `管理/变更映射.md` 中列出源路径、目标路径、配套调用方和验收门。
- 完整证据放入当前任务；本目录只保存简洁状态和链接。
- 失败和未完成项不得从交接中消失。

## 3. 验证记录

每项验证至少记录：

- 日期、环境和真实 Git 身份；
- 完整命令和工作目录；
- 实际进入的测试或检查范围；
- PASS、FAIL、SKIPPED、警告和未执行项；
- 证据能证明什么、不能证明什么；
- 是否修改了生成文件或锁文件。

历史验证只能说明绑定的历史提交。移动目录、修改代码或依赖后，必须重跑相应门，不能复制历史 PASS。

## 4. 每次任务结束

1. 更新修改记录、验收清单、变更映射和验证记录。
2. 更新 `02-当前状态与下一步.md`。
3. 检查所有改动均在授权路径内。
4. 检查 Markdown 链接、旧活动路径和重复权威副本。
5. 如获授权，commit、push，并复核远端分支。
6. 明确候选是否仍未晋升。

## 5. 晋升硬门

只有以下条件全部满足，才能请求用户批准晋升：

1. 候选范围和目标完整明确；
2. 变更映射覆盖全部候选文件及配套调用方；
3. 不依赖实验的必需验收项全部关闭；
4. 候选类型检查、测试、构建和文档检查通过；
5. 在不覆盖成熟目录的环境中完成成熟程序回归；
6. Blocker 和 Major 全部关闭，或用户明确接受剩余风险；
7. 模型身份、配置身份、适用域、单位和 provenance 一致；
8. 审查证据绑定固定提交，限制和 NO-GO 没有被删去；
9. 用户明确授权晋升；
10. 晋升在单独分支和原子提交中执行；
11. 晋升后重新验证并更新三个成熟目录的身份锚点。

## 6. 晋升时的职责映射

- 成熟理论进入 `01-最终理论`；
- 成熟程序进入 `02-模拟程序`；
- 正式状态、验证证据和审查归档进入 `03-项目资料`。

普通任务不得顺手修改这些目录。晋升完成后，当前任务工作副本可以在保留 Git 历史和正式归档的前提下清理或初始化为下一任务；不得留下两个同时声称权威的活动版本。

## 7. 明确禁止

- 根据名字或修改时间选择“最新版”；
- 整目录覆盖解决分支漂移；
- 直接把候选复制进成熟目录；
- 用局部测试替代完整验收；
- 放宽测试或删除失败证据；
- 把二维参考、未标定先验或探索性结果写成装置定量结论；
- force push、重写历史或删除无法确认身份的用户文件。
