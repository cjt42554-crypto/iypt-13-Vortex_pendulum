## 2. 目标、非目标与结论上限

目标是建立一个结果盲、可实测、可复核、fail-closed 的 A8R-HW1 硬件资格流程，并
从所有安全、正确且静态可行的候选中选择端到端吞吐接近最优的执行身份。

“充分利用硬件”不表示强制所有 CPU、GPU 和内存同时达到 100%，也不预设 GPU、
多进程、线程、WASM、原生代码或混合后端必然胜出。它表示：

1. 所有可访问且有合理概率带来实质净收益的资源类别均已被结果盲审查；
2. 所有安全且静态可行的类别均已按同一冻结协议实测，或有机器可审计的静态
   `NO-GO` / `DEFERRED-UNSAFE-TO-PROBE`；
3. 被选配置通过正确性、端到端性能、资源利用、内存、安全和热管理全部门；
4. 被选配置吞吐不低于全部安全候选最佳值的 95%；
5. 没有一个未评估的可访问资源类别仍有合理概率提供超过 10% 的净提升。

本合同不证明或解锁：

- 当前串行参考的科学正确性；
- 任一候选后端一定通过；
- 高利用率等于数值或物理正确；
- 正式程序集成；
- 规定横移、weak-FSI、三维、自由表面或实验预测。

## 6. 候选资源类别与覆盖义务

静态审查至少覆盖：

- 轨迹级独立进程或 worker 并行；
- CPU 单轨迹线程并行或域分解；
- CPU 原生、WASM SIMD 或其他向量化内核；
- GPU 计算后端；
- CPU/GPU 混合流水线；
- 内存布局、低复制审计、紧凑 trace、case shard 和确定性聚合。

允许新增静态可行候选，不得因为类别名称或既有实现偏好删除候选。若某 GPU 被无关
进程占用，不得停止、迁移、降优先级、清显存或 reset；该候选只能记录为：

`DEFERRED-UNSAFE-TO-PROBE`

静态 `NO-GO` 必须包含可复核的设备/工具/API 缺失或资源门证据；“实现复杂”“预计不
快”或纸面并行度不足均不是静态 `NO-GO`。

## 7. 硬件 inventory 与安全基线

首次性能运行前必须记录并哈希：

- CPU 型号、socket、物理核、逻辑核、NUMA、cache 和 ISA；
- `MemTotal`、`MemAvailable`、cgroup 内存上限、swap 和 OOM 计数器；
- 可访问 GPU 的型号、UUID、显存、驱动、计算 API 和占用归属；
- OS、kernel、Node、V8、编译器和关键依赖；
- 文件系统、临时目录、设备号和挂载身份；
- 可持续内存带宽基线；
- 电源策略、频率、温度和热降频计数器或明确的可用代理。

inventory 不得修改无关进程、全局 overcommit、drop caches、swap、驱动、电源策略或
系统级 affinity。

## 8. H2 代表性 probe 协议

每个候选使用 D54 尺寸和完整力身份数据路径的非科学 probe，并满足：

- 至少一次冷启动；
- 预热不少于 32 个完整步骤；
- 每个有效计时窗不少于 15 秒且不超过 60 秒；
- 至少三次有效重复；
- 另做不超过 10 分钟、可覆盖 trace 内存增长的 soak，或给出等价的内存上界证明；
- 所有 worker 启动、IPC、主机与设备传输、审计、shard 校验、聚合和规范写入均计入
  端到端墙钟；
- 不输出、保存或显示第 5.2 节的任何科学字段。

同一比较批次必须使用可比的环境负载、温度、频率和可用内存。任一次出现 OOM、swap
增长、热降频或无关进程干扰，该候选本批次全部无效。

## 9. 指标与冻结验收门

定义端到端吞吐：

$$
X=\frac{N_{\mathrm{cells}}N_{\mathrm{steps}}}{10^6T},
$$

单位为 MLUPS。定义相对串行加速比：

$$
S=\frac{T_1}{T_c}.
$$

对于使用 $R$ 个 CPU 资源单元的候选，定义并行效率：

$$
E=\frac{S}{R}.
$$

其中 $T_c$ 必须是第 8 节所述的完整端到端墙钟。当前经历过暂停和外部负载的长时串行
参考不得充当 $T_1$；必须在同一安全资源窗口使用受限非科学串行 probe 建立基线。

### 9.1 重复性门

- 每个有效配置至少三次测量；
- 墙钟变异系数不超过 5%；
- 最慢与最快之比不超过 1.10；
- 环境负载、温度、频率和可用内存可比。

### 9.2 正确性门

- H2-X：第 10 节全部精确哈希和 fail-closed 门通过；
- H2-N：第 11 节的新数值资格合同全部通过并获独立 Pro 接受；
- 不允许未注册的“性能快但结果略有不同”；
- 结果承载运行中不得自动 fallback 或切换后端。

### 9.3 性能与利用率门

被选候选必须同时满足：

1. 端到端 `S >= 1.50`；
2. 吞吐不低于全部安全候选最佳值的 95%；
3. CPU 多资源配置在未证明内存带宽饱和时 `E >= 0.55`；
4. CPU 计算窗满足至少一项：
   - 分配逻辑 CPU 的平均有效占用不低于 70%；
   - 实测内存带宽不低于本机可持续基线的 70%，且继续增加 CPU 带来的吞吐提升不
     超过 5%；
5. GPU 配置若被选择：
   - 计算窗 GPU busy 中位数不低于 60%；
   - 主机到设备传输、同步与序列化合计不超过端到端墙钟的 35%；
   - CPU 喂数不是持续单线程瓶颈；
6. 代表性 soak 中吞吐持续退化不超过 10%。

### 9.4 内存、安全与热管理门

定义系统保留：

$$
F=\max(4\ \mathrm{GiB},0.25\,\mathrm{MemTotal}).
$$

必须满足：

- `MemAvailable` 始终高于 $F$；
- swap 使用不增长；
- `memory.events` 的 `max`、`oom` 和 `oom_kill` 不增长；
- 候选峰值内存加 10% 裕量低于专用 cgroup 或等价隔离上限；
- 不触碰无关 CPU/GPU 进程；
- 不发生热降频；若只能读取频率代理，持续频率下降超过 15% 则该批次无效；
- 不修改全局 overcommit、drop caches、swap、驱动或电源策略制造 PASS。

只有第 9.1 至 9.4 节全部通过，且候选覆盖义务闭合，才能记录：

`PASS-A8R-HW1-HARDWARE-UTILIZATION`

## 12. shard、聚合与恢复语义

每个完整 case 必须生成不可变 shard。shard 只能在该 case 从 step 0 完整结束并通过
来源、有限性和结构门后原子生成，且必须包含：

- 唯一 case ID 与定义；
- scientific、execution 和 artifact 三层身份；
- scientific payload 规范哈希；
- 规范路径、SHA-256、`realpath`、设备号与 inode 证据。

完成顺序不得改变规范字节。父聚合器只有在八个唯一 shard 全部闭合后才能写规范主
产物和 sidecar；缺失、重复、损坏或来源漂移必须 fail-closed。

允许同一环境在完整 case 边界继续尚未完成的矩阵，但禁止：

- 从未注册的中间 checkpoint 恢复一个 case；
- `HW1-primary` 与 `HW1-repeat` 互用 shard；
- 使用当前串行参考的 case 对象、人口或 shard 填补 HW1；
- 根据 shard 的科学值改变调度、后端或资源配置。

### 13.2 Execution identity

### 13.3 Artifact identity

规则。

`implementationTreeSha256` 冒充旧执行身份。
