# HW2R v2 代表性硬件测量预注册合同

## 1. 身份和证据边界

机器合同身份为：

`VP-HW2-REPRESENTATIVE-QUALIFICATION-PROTOCOL-v2`

父合同为：

`VP-A8R-HW1-MACHINE-CONTRACT-v2`

本合同执行 PR-2 的以下裁决：

- HW2 v1 的十候选覆盖、安全、确定性和结果盲封装证据继续有效；
- HW2 v1 的 2 线程 OpenMP 选择因测量语义问题定性为 `INCONCLUSIVE`；
- v1 选择不得作为 H3 后端；
- 必须完整重做 candidate-scaled、代表性、全类别 HW2R v2；
- H3、`HW1-primary` 和 `HW1-repeat` 继续锁定。

本合同冻结在首次 HW2R v2 性能观察之前。它只授权非科学的硬件测量、正确性哈希、资源字段和候选分类，不授权 A8R 结果承载运行，也不形成数值、物理或实验结论。

## 2. v1 保留和 v2 替代关系

以下 v1 文件保持逐字节不变：

- v1 协议；
- v1 实现；
- 两次 v1 机器证据和 sidecar；
- v1 结果报告；
- H1 v1/v2 机器合同。

v1 的有效结论只写作：

`PASS-HW2-V1-SYNTHETIC-HARNESS-COVERAGE-SAFETY-AND-DETERMINISM`

WP-HW2 继续是 `IN_PROGRESS`。只有 v2 完整矩阵和 H2-X 或完整 H2-N 闭合后，才允许形成最终硬件选择候选结论。

## 3. 结果盲字段边界

允许持久化：

- 合同、来源、依赖、实现和环境哈希；
- 相等布尔值；
- 生命周期分项时间；
- 吞吐、加速、扩展和效率；
- CPU、GPU、内存、swap、热和 cgroup 资源字段；
- 测量有效性、候选分类和机器可审计失败。

禁止持久化或向人展示：

- 阻力、升力、力矩、功率；
- 压力、速度场和人口数组；
- 周期、频率、Strouhal、相位或频谱；
- 科学门裕量、文献距离或科学决策。

所有代表性负载必须使用合成或资格身份。不得写 A8R 规范主产物。

## 4. 候选特定计时

每个候选最多进行三次短校准。确定性放大规则为：

`ceil(previousBatchCount * clamp(20 / medianSeconds, 1.25, 16))`

正式批次规则：

- 目标窗口 20 至 45 秒；
- 硬容许窗口 15 至 60 秒；
- 三次有效正式重复；
- 至少两个 warmup 批次；
- 正式重复开始后批次数冻结；
- 三次正式重复工作量完全相同。

低于 15 秒不再是性能 NO-GO，只能记为：

`MEASUREMENT_INVALID-WORKLOAD-TOO-SHORT`

高于 60 秒只能记为：

`MEASUREMENT_INVALID-WORKLOAD-TOO-LONG`

测量无效后只能按冻结算法处理，不能人工挑选倍率，也不能只重试有利候选。

## 5. 生命周期和三层代表负载

每个候选分别记录：

1. build 或 provision；
2. cold process/device initialization；
3. warmup；
4. steady-state compute；
5. IPC 或 transfer；
6. audit；
7. shard serialization、fsync 和 hash；
8. final aggregation；
9. cleanup。

代表负载分为三层：

- R0：u32 执行框架 smoke，只验证设备、worker、IPC、摘要和证据封装，不参与最终选择；
- R1：D54 A8R 操作图代表负载，必须覆盖 Float64 D2Q9、MRT、Guo forcing、Brinkman、scatter streaming、开放边界、pre/post 人口、独立力身份、A2、场诊断和 shard/hash；
- R2：冻结八 case 成本结构代表负载，保留 D24/D36/D54 和相位比例，测量调度空洞、负载不均、聚合和峰值内存。

只有 R1 和 R2 可以决定 H3 执行架构。

## 6. 完整候选矩阵

必须覆盖全部候选类别：

- trajectory process parallel；
- single-trajectory CPU domain/thread；
- native 或 WASM SIMD；
- GPU compute；
- CPU/GPU hybrid；
- data-layout、shard 和 aggregation。

CPU 至少覆盖 1、2、4、8、12、16 个物理核；24、32 逻辑线程在资源安全时作为 SMT 条件点。必须测量 pinning、单 CCD/L3、跨 CCD/L3、case process pool 和成本感知调度。

GPU 必须使用 persistent context、persistent buffers、批处理和设备侧计时，并获得至少 30 个有效遥测样本或等价高频计数。H2D、D2H、同步、审计和一次性初始化分别计时。

hybrid 固定测试 CPU 占比 0.25、0.50、0.75 三种分割。分割只可基于结果前成本模型，禁止使用科学值。

## 7. 安全门

所有正式代表测量必须在有限内存 cgroup 中执行，并同时满足：

- 系统保留至少 4 GiB 或总内存 25%，取更大者；
- 候选静态内存上界另加 10% headroom；
- swap 增量为零；
- cgroup OOM 和 memory high 事件增量为零；
- 不停止、迁移、降优先级或 reset 无关进程；
- 存在外来 GPU 进程时只记 `DEFERRED-UNSAFE-TO-PROBE`；
- 热 throttle 或频率下降超过 15% 时整批作废，不选择性保留。

## 8. 选择语义

固定顺序为：可访问、测量有效、正确性、安全、数值身份、利用或饱和、性能、全体合格候选最佳吞吐、95% 集合、风险决胜。

最终候选必须同时满足：

- 代表性端到端加速至少 1.50；
- 达到全部合格候选最佳吞吐的至少 95%；
- 重复墙钟 CV 不超过 5%；
- 最慢/最快比不超过 1.10；
- CPU 扩展或 GPU 持续利用证据闭合；
- 通过 H2-X，或通过完整 H2-N；
- 安全门通过。

如果仍有测量无效且可能提供超过 10% 净收益的候选，选择器必须 fail-closed。若多个候选处于 95% 集合，按科学语义风险、内存、治理复杂度、候选 ID 的顺序决胜。

## 9. 时间顺序和停止点

固定时间顺序为：合同和 schema、合同测试、测量器/遥测器/选择器、代表负载、实现提交推送、首次性能观察、完整机器证据和 sidecar。

本合同提交不包含测试、实现或性能观察。后续实现也必须先独立提交并推送。

HW2R v2 最高通过码为：

`PASS-HW2R-REPRESENTATIVE-MEASUREMENT`

它本身仍不是 H3 解锁。完整批次必须停在：

`READY-FOR-PR2B-H3-UNLOCK-REVIEW`
