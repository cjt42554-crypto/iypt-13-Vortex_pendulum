# H1 v2 机器合同冻结说明

## 1. 身份与原因

活动机器合同身份为：

`VP-A8R-HW1-MACHINE-CONTRACT-v2`

它由裁决 `IYPT13-PR1-R0-HOST-SHUTDOWN-ROUTE-DECISION-v1` 触发。原机器合同 v1
要求 H2 前存在已封存的完整串行参考；主机关机后该参考没有形成，规范主产物、sidecar
和可恢复 checkpoint 均不存在。因此 v1 保留为不可改写的历史合同，活动实现只能读取
v2。

冻结的父级 Markdown 合同继续逐字节不变。v2 只覆盖已经被事件事实破坏的串行前置，
不放宽候选覆盖、结果盲字段、性能门、资源门、H2-X/H2-N、shard、三层 provenance
或两次新鲜 H3 全量运行规则。

## 2. 事件覆盖

v2 固定以下事实：

- 原串行运行的终止身份为
  `A8R-V2P1-INTERRUPTED-SERIAL-ATTEMPT-20260831`；
- 分类为 `INCONCLUSIVE-R0-HOST-SHUTDOWN-NO-CANONICAL-ARTIFACT`；
- 完整串行参考未达到，科学 payload 不存在；
- 旧完整串行重跑、checkpoint 恢复和部分进度抵扣均未授权；
- H2 的串行前置改为
  `PASS-R1I-INTERRUPTED-SERIAL-ATTEMPT-EVIDENCE-SEALED`；
- H2 只可使用绑定冻结源提交的受限非科学 oracle；
- 下一两个结果承载长时运行必须是 `HW1-primary` 和 `HW1-repeat`。

## 3. 活动实现约束

活动实现必须显式验证合同 ID 为 `VP-A8R-HW1-MACHINE-CONTRACT-v2`。若传入 v1、缺失
合同、未知合同或试图自动回退，必须以 `NO-GO-HW1-V1-ACTIVE-MISUSE` 或更严格失败码
停止。

G1 只允许无结果架构、静态 inventory、合成测试和轻量验证。不得运行 H2 性能 probe、
D54、GPU 或内存带宽压力，不得读取科学 payload，也不得生成 A8R 规范主产物。

## 4. 时间顺序与验证

本提交只冻结 v2 合同、schema 和 PR-1 映射，不包含活动实现或性能观察。下一独立提交
必须增加 v2 合同测试以及 v1 误用、自动 fallback、完整旧串行重跑和 partial credit 的
负测试。测试通过之后才可编写依赖 v2 的活动 H1 实现。

本文件不进入通用 Markdown 格式门。根据用户最新范围，格式门只覆盖
`01_最终理论/**/*.md` 和 `90_候选工作区/交接说明_current.md`。
