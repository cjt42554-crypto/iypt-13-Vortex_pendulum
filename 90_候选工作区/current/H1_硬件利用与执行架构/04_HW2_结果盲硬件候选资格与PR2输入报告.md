# HW2 结果盲硬件候选资格与 PR-2 输入报告

## 1. 结论

冻结后、结果盲的 HW2 资格运行已完整执行，机器证据记录为：

`PASS-A8R-HW1-HARDWARE-UTILIZATION-CANDIDATE-ONLY`

冻结评估器在三个 `PROBE_PASS` 候选中选出：

`hw2-native-openmp-domain-v1-w02`

它在同窗口 native 串行基线上的加速比为 1.995669，端到端吞吐为
1355.535 MLUPS，三次重复墙钟变异系数为 0.001221。

但是，这不构成 WP-HW2 的最终 PASS，也不解锁 H3。本轮只证明固定合成工作负载下
的候选执行路径资格；尚未建立 H2-X 对冻结科学源的精确执行等价，也未冻结、执行或
接受 H2-N。`HW1-primary`、`HW1-repeat`、完整八轨迹、D54 和任何结果承载运行仍然
禁止。科学结论仍为 `NONE`。

本轮还暴露了一个必须由 PR-2 独立判断的合同/测量边界：16 核 OpenMP 和 GPU 的原始吞吐
显著高于被选 2 线程候选，却因为同一基线工作量在高加速候选上不足 15 秒、以及 GPU
采样门而被排除。结果出现后不得在本地修改门值或选择规则，因此必须停在 PR-2。

## 3. 静态主机事实

- CPU：AMD Ryzen 9 9955HX，16 个物理核、32 个逻辑 CPU，单 socket、单 NUMA node。
- ISA：AVX2、AVX-512 和 FMA 可用。
- 内存：约 15.9 GB；资格开始时 `MemAvailable` 约 10.3 GB。
- GPU：NVIDIA GeForce RTX 5060 Laptop GPU，8,546,942,976 bytes 显存，CUDA Driver JIT
  可访问，扫描时无外来计算进程。
- 编译链：GCC 13.3、OpenMP 和 libcrypto 可用；`nvcc` 不可用，因此 GPU 候选使用
  CUDA Driver API 动态 JIT PTX。
- 可持续内存带宽冻结基线为 51,939,187,860 bytes/s，三次校准。

该 inventory 未修改 swap、drop caches、overcommit、驱动、电源策略、全局 affinity 或无关进程。

## 6. PR-2 必须独立审查的边界

### 6.1 计时窗与充分硬件利用

合同要求每个有效候选的计时窗为 15–60 秒。本实现将串行家族校准到约 55 秒，然后对
同一工作量比较所有候选。因此，加速比明显高于约 3.67 的候选会必然低于 15 秒。

实测中，16 核 OpenMP 的 14.436 倍加速、9805.743 MLUPS，以及 GPU 的 153.968 倍合成
加速、104580.953 MLUPS，都因此不是 `PROBE_PASS`。冻结选择器只在已通过的三个候选
中计算“最优吞吐”，因而选中 2 线程 OpenMP。这个选择是对当前机器实现的忠实执行，
但它是否满足原合同“全部安全候选最优吞吐 95%”的本意，不能由本轮自行追认。

### 6.2 GPU 采样语义

GPU 候选的完整重复仅约 0.35 秒，资源轮询间隔为 250 ms。证据记录的 GPU busy 聚合值为
0，同时传输占比约 42.6%，并保守记录 CPU 喂数瓶颈。这足以按冻结实现宣告本次 GPU
probe NO-GO，但不足以归纳“GPU 本身无效”或“GPU 不值得使用”。

### 6.3 科学等价与受保护路径

本次固定 u32 工作负载只校验执行和资源路径，不是冻结 A8R 科学内核。Native OpenMP、
CUDA 和混合路径也尚未并入受保护的正式模拟程序。因此不得将摘要一致越级成 H2-X；
若后续候选改变浮点、并行归约或科学内核语义，则需按 H2-N 的结果前合同处理。

   采样之间是否存在合同或实现级缺陷。

   证据和停止条件是什么。
3. 若需新版合同、协议或全矩阵重做，哪些门必须保留，如何避免结果后调参或只重试有利
   候选。
4. 从全仓尺度审查技术债、重复实现、运行器、合同和证据体系，判断是否需要局部或大范围
   重构，并给出有依赖关系、验收门和停止点的完整下一阶段规划。
5. 哪些后续变更需要修改受保护路径，应按精确文件进行哪些授权；在任何结果承载运行之前，
   H3 的精确解锁条件和结论上限是什么。
