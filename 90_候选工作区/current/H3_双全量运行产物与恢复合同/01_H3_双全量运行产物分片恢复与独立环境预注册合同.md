# H3 双全量运行产物、分片、恢复与独立环境预注册合同

## 1. 身份和当前锁

机器合同身份为：

`VP-H3-DUAL-FULL-RUN-ARTIFACT-SHARD-RECOVERY-CONTRACT-v1`

当前只允许 H3 结果前准备和纯合成 dry-run。任何正式 solver 构造、完整八 case 结果承载运行、`HW1-primary` 或 `HW1-repeat` 都继续禁止。

唯一合法解锁码必须来自后续集中 PR-2B：

`UNLOCK-HW1-PRIMARY-AND-HW1-REPEAT-ONLY`

自动解锁、环境变量解锁、CLI 解锁或沿用旧授权均无效。

## 2. 两个运行身份和独立环境

固定运行顺序为：

1. `HW1-primary`，环境 `H3-ENV-PRIMARY`；
2. `HW1-repeat`，环境 `H3-ENV-REPEAT`。

primary 完整结束并封存前不得启动 repeat。两个环境必须：

- 使用新目录；
- 独立安装依赖；
- 独立 preflight；
- 独立临时根目录；
- 来自同一结果前实现提交；
- 使用相同依赖锁、编译器/驱动和设备身份；
- 不共享 shard、checkpoint、cache、临时文件或 inode；
- 不读取对方结果。

PR-2B 前可以建立并封存两个环境，但 `firstCaseStarted` 必须为 false。

## 3. case 矩阵和调度

两个运行都必须从第一 case、step 0、新鲜初态完整执行冻结八 case。

调度只允许读取：case ID、直径、冻结步数、冻结成本权重和 worker 资源包络。不得依据任何科学值调整顺序、worker 或资源。

## 4. atomic case shard

每个 case 只有在从 step 0 完整结束、有限且内部结构通过后，才允许写入 final shard。

原子顺序固定为：

1. 在该运行专属目录写 `.partial-*`；
2. fsync partial 文件；
3. 验证规范哈希；
4. rename 为 final shard；
5. fsync 父目录；
6. exclusive-create sidecar；
7. fsync sidecar 和父目录。

final shard 和 sidecar禁止覆盖。JSON gzip 固定 level 9、mtime 0；禁止时间戳字段和非有限 JSON 值。

## 5. 中断恢复

主机异常后，只允许在同一 run、同一环境、同一来源、同一实现、同一依赖身份内继续使用已经完整且哈希闭合的 final shard。

固定规则为：

- 中断 case 必须从 step 0 重跑；
- `.partial-*` 只能隔离或删除，不能升级；
- primary 和 repeat 不能互用 shard；
- 不允许跨实现、来源、依赖或环境复用；
- 不允许 incomplete-case checkpoint resume；
- 恢复判断只读身份和完成字段，不读科学值；
- 旧中断串行运行的任何数据、checkpoint 或部分进度均不能使用。

## 6. 聚合和三层 provenance

聚合器要求恰好八个、case ID 唯一、来源/实现/依赖/run 身份一致的 shard。missing、duplicate、corrupt 或 drift 必须 fail-closed。规范排序键为 case ID，execution 字段不得进入 scientific payload。

三层 provenance 分离为：

- scientific：case、solver、科学合同、scientific payload 规范哈希；
- execution：backend、scheduler、worker、device、编译器/驱动、资源窗口、实现提交；
- artifact：run、environment、shard 路径、stored/canonical/sidecar/aggregation 哈希。

三层不得别名或相互替代。

## 7. PR-2B 前 dry-run

PR-2B 前 dry-run 只能使用合成 payload，且不得构造正式 solver。必须覆盖：

- environment seal；
- case plan；
- atomic shard 和 sidecar；
- 完整 shard 继续使用；
- incomplete case 从头重启；
- cross-run 和 cross-commit 拒绝；
- missing、duplicate、corrupt、source drift 和 worker failure；
- deterministic aggregation。

dry-run 通过码为：

`PASS-H3P-ARTIFACT-SHARD-RECOVERY-AND-ENVIRONMENT-DRY-RUN`

结果前准备总通过码为：

`PASS-H3P-RESULT-BEFORE-READINESS-CANDIDATE-ONLY`

这两个码都不表示 H3 已运行或已解锁。

## 8. 安全和停止点

每个正式运行开始前都必须重新检查 PR-2B 精确解锁、clean main parity、来源/实现/依赖/environment seal、输出不存在、有限内存 cgroup、系统保留、swap/OOM 基线、GPU 外来进程安全和无其他结果承载运行。

本批次只建立环境和 dry-run 证据，不执行 H3。统一停止状态为：

`READY-FOR-PR2B-H3-UNLOCK-REVIEW`
