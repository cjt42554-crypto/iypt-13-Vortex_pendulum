# H2-X 精确执行等价预注册合同

## 1. 身份和目标

机器合同身份为：

`VP-H2X-EXACT-EXECUTION-EQUIVALENCE-CONTRACT-v1`

H2-X 的目标是证明：候选 scheduler、process/worker pool、atomic case shard 和 deterministic aggregator 只改变执行调度和产物封装，不改变冻结 A8R 单 case 的科学字节身份。

最高通过码为：

`PASS-H2X-EXACT-SCIENTIFIC-EXECUTION-EQUIVALENCE-CANDIDATE-ONLY`

该通过码只证明候选执行等价，不证明 A8R 物理模型、装置预测或实验事实。

## 2. 允许和禁止的改变

允许：

- case process/worker 隔离；
- 只依赖冻结成本字段的结果盲调度；
- atomic case shard；
- shard 验证和确定性聚合；
- execution provenance；
- 同一运行身份内的完整 case 边界恢复。

禁止：

- 改变 case 内浮点运算顺序；
- 改变求解算法、精度、人口布局、边界顺序或力归约；
- 改变冻结 case、科学门或来源；
- 使用科学值调度；
- silent fallback；
- 运行完整八 case 结果承载矩阵；
- 写 A8R 规范主产物。

正式 `lbm.ts` 和既有 A8R 文件均只读导入并绑定 SHA-256。

## 3. 八 case 缩短资格矩阵

资格矩阵从冻结八 case 定义派生，只覆盖资格步数；正式研究定义保持不变。

- D24 两 case：总步数 96，discard 32；
- D36 两 case：总步数 64，discard 24；
- D54 baseline 两 case：总步数 32，discard 8；
- D54 minus-half-cell 两 case：总步数 32，discard 8。

oracle 和候选必须使用同一派生定义的规范字节。该矩阵不得命名为 research matrix，也不得形成科学判定。

## 4. 逐字节门

必须逐项相同：

1. 八 case 定义和全部来源绑定；
2. 新鲜初态人口原始字节；
3. 分析前 checkpoint 人口；
4. 分析第一步 pre/post 人口；
5. 冻结审计步 pre/post 人口；
6. 每个分析步的力身份摘要哈希；
7. 缩短完整 case 的 scientific payload 规范哈希；
8. 1 worker 与选中 worker 数；
9. canonical、reverse 和 descending-cost 完成顺序；
10. 三个独立轻量环境。

人口数组采用 little-endian Float64 原始字节后计算 SHA-256。科学标量和数组只允许在进程内形成规范哈希，随后立即丢弃；证据不得持久化或向人显示这些值。

## 5. scheduler 和 shard 负测试

worker 数固定覆盖 1、2、3、4、内存安全上限和最终 HW2R 选中数。scheduler 只能读取 case ID、直径、冻结步数、冻结成本权重和 worker 资源包络。

以下负例必须全部 fail-closed：

- missing shard；
- duplicate case ID；
- corrupt bytes；
- source 或 contract drift；
- worker 非零退出或 signal；
- partial shard；
- cross-run 或 cross-implementation shard；
- execution 字段进入 scientific payload；
- scientific value 进入证据；
- runtime fallback。

## 6. 独立环境和安全

必须有三个新目录和独立依赖安装。三者绑定相同来源和候选提交，但不得共享 shard、checkpoint、cache、临时文件或 inode，也不得读取其他环境结果。

D54 资格必须在有限内存 cgroup 中通过，系统保留至少 4 GiB 或总内存 25%，swap 和 OOM 增量为零，不操作无关进程。

## 7. 失败语义和停止点

来源、初态、人口、力身份、payload、调度、shard、provenance 或 fallback 任一门失败，都必须保存只含哈希、布尔值、资源和失败码的证据并停止。不得改门后重试，也不得把 H2-X 失败自动降级为可接受近似。

如果候选改变浮点或不能逐字节闭合，只能进入已冻结的 H2-N 身份。

H2-X 通过也不解锁 H3。完整批次必须在 `READY-FOR-PR2B-H3-UNLOCK-REVIEW` 停止。
