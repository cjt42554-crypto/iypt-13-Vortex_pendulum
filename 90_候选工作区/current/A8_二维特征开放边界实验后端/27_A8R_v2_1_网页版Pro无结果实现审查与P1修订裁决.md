## 3. 可接受的核心实现

### 3.1 人口读取与正式源只读边界

实现先将正式运行时人口与公开 checkpoint 逐元素比较，随后只把脱离正式
求解器的副本传入候选审计路径。候选代码没有写回正式人口、力数组或
checkpoint，也没有复制正式碰撞实现。

这一边界原则上可接受。

### 3.2 控制体人口动量恒等式

实现使用固定内部控制体，按步前/步后人口和穿越控制面的 D2Q9 目的格点人口
构造：

$$
\boldsymbol F_{\mathrm{CV,raw}}^n
=
-\left(
\boldsymbol P_\Omega^{n+1}
-\boldsymbol P_\Omega^n
+\boldsymbol\Phi_\Omega^n
\right).
$$

控制体及一链路 halo 位于全局边界内部；非零 mask 和重建 Brinkman 力
支撑必须位于控制体内。合成测试覆盖八个移动方向、进出链路符号、局域动量
变化、支撑拒绝和零力场。

该结构与正式 `lbm.ts` 的碰撞—迁移时序相容，可保留为正式原始
Brinkman 反力的候选离散身份。它仍不是连续应力积分或物理载荷真值。

### 3.3 A2 重算与读取屏障

A2 修正由步前/步后人口独立重建的宏观量形成：

$$
\Delta\boldsymbol P_\chi^n
=
\sum_{\boldsymbol x}
\chi\left(
\rho^{n+1}\boldsymbol u^{n+1}
-\rho^n\boldsymbol u^n
\right).
$$

原始力和 A2 残差使用分离门；正式比较 getter 只有在全部独立量形成后才可
读取。合成测试也证明原始力失败不能由 A2 修正抵消。

该门只验证 A2 同一公式的独立实现一致性，不是第二种物理取力法。

### 3.4 周期、趋势和双相位屏蔽

实现保持：

- 完整分析窗全部原始正斜率过零点；
- 唯一选择最后 7 个交叉；
- 六周期闭区间 `1/0.24 <= T_j <= 1/0.15`；
- 禁止跳过不合格交叉寻找替代点；
- 端点插值、复合梯形积分和实际时长加权；
- 周期包络 Minkowski 差三值门；
- D54 四条轨迹、全部 6 个无序轨迹对、每指标每对 36 个逐周期比较；
- 平均阻力、原始升力 RMS、去均值升力 RMS、平均周期四类指标；
- 未分辨先于路线 NO-GO 的终局优先级。

没有发现会把未分辨证据错误提升为 PASS 或 NO-GO 的核心逻辑错误。

### 3.5 A8Q 规范锚和 LFS 指针守卫

A8Q 锚加载器会先检查 LFS 指针，再核验压缩对象字节数、压缩 SHA-256、
sidecar、解压规范 JSON 字节数和规范 SHA-256，并以流式方式选取两条
$D=24$ 锚。

这一实现满足上一轮要求，可保留。

## 4. 阻塞问题

### 4.1 产物断言器的 sidecar 换行错误

研究运行器写出的 sidecar 明确使用两个 `"\n"`：

```js
canonicalSha + "  " + canonicalName + "\n"
  + storedSha + "  " + storedName + "\n"
```

但产物断言器中的期望字符串实际写成：

```js
canonical.sha256 + "  " + canonicalName + "\
"
  + stored.sha256 + "  " + storedName + "\
"
```

JavaScript 中反斜杠加物理换行是行续接，不会产生换行字符。因此断言器构造
的是两行内容直接拼接的单行字符串。任何由当前运行器合法生成的 sidecar
都会在该断言处被错误拒绝。

现有小型工件测试只测试了 `verifyArtifactIdentity()`，没有执行产物断言器
本身，所以没有发现此错误。

这是进入烟雾或研究前的确定性阻塞问题。

### 4.2 独立完整复跑门不是 fail-closed

当前产物断言器把 repeat 路径设为可选：

- 未提供 repeat 时，脚本仍可正常结束，只输出
  `independentFullRepeatClosed: false`；
- 若把同一个文件同时作为 primary 和 repeat，字节比较必然为真，脚本会输出
  `independentFullRepeatClosed: true`；
- 脚本没有要求两个规范化绝对路径不同。

因此当前断言命令既不能强制完整复跑，也不能排除“同一文件与自身比较”。
这与合同中的独立完整复跑门不相容。

P1 必须要求：

1. repeat 参数必填；
2. primary 与 repeat 的规范化绝对路径必须不同；
3. 两份 sidecar 路径也必须不同；
4. 缺少 repeat、路径相同、任一 gzip 或 sidecar 不同均非零退出；
5. 新增 CLI 或等价端到端测试，不能只测试底层 helper。

路径不同仍不能单独证明独立执行。最终研究阶段还应由交接/资格报告记录第二次
运行从干净环境和第一个算例开始；但这不需要在当前个人科研原型中建立复杂的
不可伪造证书链。

### 4.3 缺少后实现执行授权门

当前 `package.json` 已直接暴露完整八轨迹运行入口，运行器在前置检查完成后
立即构造正式求解器并执行研究矩阵。

但是当前前置检查只绑定了上一份“允许建立无结果实现”的 Pro 裁决，并没有
绑定“无结果实现审查通过、允许正式烟雾或研究运行”的后续裁决。换言之，
代码层已经可以绕过当前人工停止门直接运行完整矩阵。

P1 必须在**第一个正式求解器构造之前** fail-closed。最简单可接受的处理是：

- 暂时移除或硬锁 `brinkman-multiresolution-v2-1` 研究入口；
- 缺少新的、精确绑定的后实现 Pro 授权时立即抛错；
- 当前 P1 不自行定义烟雾或研究授权为已满足。

完成 P1 后，再由独立 Pro 决定是否只解锁正式 40 步烟雾。不得由 P1 自动解锁
八轨迹矩阵。

### 4.4 运行时依赖身份链不完整

A8R 运行适配直接导入：

- `A8_公开规定横移圆柱基准/src/benchmark-metrics.ts`。

复用的 A8Q 分析又传递依赖：

- `A8_公开规定横移圆柱基准/src/benchmark-contract.ts`；
- `A8_公开规定横移圆柱基准/src/benchmark-metrics.ts`。

这些文件会影响均值、RMS、Strouhal、成熟性或文献观察，但当前
`IMPLEMENTATION_TREE_PATHS`、A8Q 树路径和普通来源 SHA 收集均未覆盖它们。
候选 `package-lock.json` 也未纳入实现身份。

因此这些运行时依赖可以在不触发当前前置门的情况下漂移。至少
`benchmark-metrics.ts` 会直接改变主指标和成熟性，是阻塞性来源身份缺口。

P1 必须把所有直接和传递的结果相关运行时依赖纳入精确字节身份，至少包括：

- `A8_公开规定横移圆柱基准/src/benchmark-metrics.ts`；
- `A8_公开规定横移圆柱基准/src/benchmark-contract.ts`；
- 候选包 `package-lock.json`；
- 其余由静态导入图发现、会进入 A8R 运行或断言的非标准库文件。

同时应在正式烟雾前执行一次干净 `npm ci`。

### 4.5 P1 提交身份需要可修订

当前前置门要求 `IMPLEMENTATION_PATHS` 中每个文件的“最后一次修改提交”完全
相同。若 P1 只修复断言器、前置门和测试，未改动的科学文件仍指向旧提交，
前置门会拒绝新的实现树。

P1 应改为：

- 以一个明确的 P1 实现提交为身份；
- 校验该提交下完整实现路径集合的字节树；
- 要求工作树字节与该提交一致；
- 不要求每个文件都必须在 P1 中被人为改写。

不得为了满足身份门而给无关科学文件添加无意义改动。

## 5. 非阻塞风险

完整产物会在每个分析步保存较大的独立力审计对象，八轨迹总分析样本数较高。
正式烟雾阶段应记录内存峰值和产物尺寸预估。该问题目前属于资源风险，不构成
合同逻辑错误，也不能在未运行前断言必然失败。
