## 3. 当前运行与结果身份的精确顺序

### 3.1 当前串行参考必须自然完成

在当前进程退出前只允许：

- 读取 PID、启动时间、PGID、SID、CPU 时间、RSS、进度文本和退出状态；
- 只读观察 `MemAvailable`、swap、OOM、热降频和规范产物路径；
- 在原有终端中接收程序已经定义的输出；
- 在独立治理工作区写运行现场记录。

不得：

- 再次发送 `SIGSTOP`、`SIGTERM` 或 `SIGKILL`，除非出现本文件第 13 节的真实异常；
- 在旧工作区 `pull`、`checkout`、`rebase`、安装新依赖或放置候选源码；
- 通过调试器、heap dump、checkpoint、人口数组或中间对象读取科学结果；
- 把当前暂停过的墙钟时间当成硬件性能基线。

### 3.2 当前运行结束后的封存

当前进程自然结束后，应在旧工作区不做 Git 同步的前提下先记录：

- 三进程最终身份和退出状态；
- 八轨迹完成状态；
- 终端最终摘要；
- 工作区 `HEAD`、`origin/main` 和 clean 状态；
- 规范 gzip、sidecar、`.partial-*` 的存在性；
- gzip 和 sidecar 的 `realpath`、设备号、inode、字节数和 SHA-256；
- 现有主产物断言器的完整输出。

退出码 `2` 与执行失败必须区分。若八轨迹、gzip、sidecar 和断言链完整，退出码 `2`
可以只是冻结科学判定非 PASS，不能据此删除产物或自动重跑。

封存完成后，把完全相同的 gzip、sidecar、原始终端记录和初始报告转移到最新
`main` 的独立干净工作区；转移前后逐字节核验。旧工作区仍不得更新。

### 3.3 原冻结复跑环境的处置

原来为旧串行实现冻结的独立复跑环境：

- 不再执行旧串行八轨迹；
- 不得拉取当前主产物；
- 只作为“原 v2.1 复跑曾在结果前冻结”的历史证据保留；
- 可以记录路径、HEAD、设备号和 inode 后归档；
- 不得复用于 A8R-HW1 主运行或复跑。

### 3.4 A8R-HW1 的从头重跑义务

硬件后端确定后，必须从同一个已提交、已推送、结果前冻结的 A8R-HW1 实现提交建立
两个独立环境：

- `HW1-primary`；
- `HW1-repeat`。

两者必须分别：

- 独立安装依赖；
- 独立完成来源前置门；
- 从第一个 case、step 0 和新鲜初态运行全部八轨迹；
- 不共享 checkpoint、case shard、缓存、临时文件、inode 或中间人口状态；
- 不读取对方结果；
- 完成各自规范产物和 sidecar。

任何“当前串行参考 + HW1 repeat”或“HW1 primary + 旧串行 repeat”的组合均不构成
独立复跑闭合。

## 4. “充分利用硬件算力”的操作定义

“充分利用”不等于强制所有 CPU、GPU 和内存同时达到 100%，也不等于优先采用 GPU。
它指：

1. 对本机所有可访问且可能产生实质净收益的计算资源类别完成结果盲可行性审查；
2. 对静态可行且不干扰无关任务的类别执行代表性实测；
3. 从全部安全、正确的候选中选择端到端吞吐接近最优的配置；
4. 被选配置的主要瓶颈资源得到高利用，而不是因单线程调度、复制、序列化或主机喂数
   造成大面积空闲；
5. 所有启动、数据搬运、审计、聚合和产物写入成本都计入端到端时间；
6. 正确性、来源身份、内存安全和结果盲边界优先于利用率数字。

允许审查的候选类别包括但不限于：

- 轨迹级独立进程或 worker 并行；
- CPU 单轨迹域分解或线程并行；
- CPU 原生、WASM SIMD 或其他向量化内核；
- GPU 计算后端；
- CPU/GPU 混合流水线；
- 不改变科学路径的内存布局、分块、流式 trace 和 case shard 重构。

不得因为类别名称或先前方案而预设最终选择。最低语义风险的精确调度路径应先验证，
但若它未达到硬件利用门，不能据此禁止继续审查更深的 CPU 或 GPU 后端。

若某 GPU 正被无关进程占用，不得暂停、终止、迁移、降优先级、清显存或 reset。
该 GPU 候选应标为 `DEFERRED-UNSAFE-TO-PROBE`，待自然安全窗口出现后再测；不能把
暂时占用误写成 GPU 技术不可行。

## 5. 现有执行链的独立技术审查

### 5.1 八轨迹调度层

当前 `runBrinkmanMultiresolutionV2P1Qualification()` 对冻结 definitions 使用同步
`.map()`，每条轨迹完整返回后才进入下一条。运行器和 package script 均为单 Node
入口，没有资源规划器、任务图或 case worker 池。

结论：这是显著的并行度技术债，但不是唯一瓶颈。

### 5.2 单轨迹全场复制与二次审计

每个分析步当前依次执行：

1. `checkpoint()` 复制完整 `9N` 人口；
2. 再次 `.slice()` 形成独立步前人口；
3. 正式求解器执行一步；
4. 再按同样路径复制完整步后人口；
5. 独立控制体力身份在全场重建宏观量、Brinkman 力和链路通量；
6. 再读取正式宏观场并执行场诊断。

这一结构把一次分析步变成多次全内存带宽扫描。此前 D54 静态内存下界和实际 RSS
已经证明，内存与复制是一级约束。单纯增加 worker 可能很快从 CPU 空闲转为内存带宽、
GC 或可用内存瓶颈。

结论：必须把复制与审计数据路径纳入硬件重构，不能只改顶层调度器。

### 5.3 trace 与产物生命周期

每个分析步把包含多层对象、逐项残差、绝对账和正式比较值的记录推入 JavaScript
`trace` 数组。完整 case 返回后，顶层还保留已完成 case 对象，直到八轨迹全部完成，
最后才一次性写 gzip 和 sidecar。

后果包括：

- JS 对象和 GC 开销高；
- 峰值内存随分析窗长度增长；
- 已完成 case 在进程崩溃时没有独立认证产物；
- 无法在 case 边界安全恢复；
- 最终写入前存在单点失败窗口；
- 多 worker 并发的可行度被 trace 常驻内存压低。

结论：应改为确定性列式或紧凑 trace、完整 case shard 和最终聚合；不得通过删除科学
字段来“优化”。

### 5.4 正式 LBM 内核

正式 `D2Q9MrtBrinkmanSolver` 是纯 TypeScript/JavaScript 同步内核：

- 两个 `9N` AoS 人口数组；
- 六个 `N` 宏观、mask 和力数组；
- `computeMacros()` 与 `collideAndStream()` 均为嵌套 JS 循环；
- streaming 使用按 cell 的方向循环、scatter 写入和分支选择；
- 每步 `streamed.fill(0)`；
- 固定圆柱路径仍逐格计算 `Math.hypot` 和过渡区 `Math.sin`；
- 全局力和功由单线程标量归约。

该实现清楚、确定、审计性强，但数据布局、scatter、重复 mask 计算和串行归约对
SIMD、GPU 和域分解不友好。

结论：正式内核存在中长期性能债；立即全仓重写风险过高，应在候选后端先验证。

### 5.5 正式程序 worker 与 CLI

正式 GUI 使用一个 Web Worker，使 UI 不被阻塞，但 worker runtime 同时只允许一个
active run。CLI 也只有单求解器入口。GUI worker 是响应性隔离，不是硬件并行框架。

结论：已有 worker 边界可复用，但必须新增资源规划、worker pool、后端身份和可取消
任务图，不能把“有 Web Worker”描述为已充分利用多核。

### 5.6 私有数组旁路

候选审计通过 TypeScript 强制转换读取正式 solver 的私有 `rho/ux/uy/mask` 和
`distributions`，再与公开 checkpoint 比较。这提高了当前证据强度，但说明正式模块
缺少稳定、零额外复制或受控只读的诊断接口。

结论：候选阶段可维持只读旁路；正式集成前应提供版本化 buffer lease、只读视图或
确定性审计回调，禁止无界暴露可变数组。

### 5.7 provenance 与执行身份耦合

A8R preflight 对合同、测试、runner、asserter、package、lockfile、正式源和静态依赖
闭包做强绑定。这是重要优点，但当前结果对象只有一个“implementation tree”概念，
把科学公式、数值内核、调度器、序列化和安装环境耦合在一起。

因此，改变调度器即使不改变单轨迹算术，也无法诚实地伪装成旧实现；这正是本裁决
要求新主/复跑对的原因。

结论：新合同必须拆分 scientific identity、execution identity 和 artifact identity。

### 5.8 测试与持续集成

仓库有大量单元、合同、产物和人工复跑测试，但 GitHub Actions 当前只执行 Markdown
数学检查；没有自动运行正式程序测试、候选测试、TypeScript、构建、确定性 smoke
或性能回归。

结论：验证内容并不缺，自动化入口和性能回归缺失。该债务应在硬件工程中补齐，但
CI 不能替代本机硬件资格。

### 5.9 跨阶段重复代码与大型模块

A8B 到 A8R 形成多个合同、runner、support、artifact asserter 和报告；正式程序中
也存在四万字节级 config、两万字节级 UI/求解器模块和五万字节级分析脚本。部分重复
是结果盲冻结的证据要求，不能简单去重；但公共的哈希、shard、资源规划、断言和
流式写入功能应抽成版本化基础设施。

结论：不应在本轮做无目的全仓格式化或目录重排。只重构被硬件目标和证据完整性直接
驱动的执行与数据平面。

## 6. 技术债总裁决：分阶段中到大规模重构

总裁决不是“保持现状”，也不是“立即重写整个仓库”。

应执行：

- 候选 A8R 执行与数据平面：大范围、分阶段重构；
- 正式高保真内核与 runner：候选通过后再做局部到中等规模集成；
- 前向理论、结构性理论、ROM、普通 UI 和无关分析：保持现状，除非测量证明其是
  当前目标的实际瓶颈；
- 旧合同、旧产物和旧裁决：保持不可变历史，不做批量迁移。

优先级如下。

| 优先级 | 技术债 | 必须动作 |
|---|---|---|
| P0 | 科学、执行、产物身份混合 | 新建三层身份和机器合同 |
| P0 | 八轨迹同步串行 | 资源感知任务图与确定性调度 |
| P0 | 每步多份 `9N` 全人口复制 | 测量并建立可证明等价的低复制审计路径 |
| P0 | 对象化 trace 常驻与全结束后单次写入 | 紧凑 trace、完整 case shard、确定性聚合 |
| P0 | 无 case 边界容错 | shard 完成即认证；主/复跑仍禁止互相复用 |
| P1 | 正式内核 AoS、scatter、重复 mask、串行归约 | 候选 CPU/GPU/原生后端对比 |
| P1 | 私有数组旁路 | 版本化只读诊断接口 |
| P1 | 单 Web Worker 与单 CLI | worker pool、资源规划、取消和进度协议 |
| P1 | 无代码/性能 CI | 新增测试、构建、smoke 与性能退化检查 |
| P2 | 阶段脚本和大型模块重复 | 在身份不变条件下抽取版本化公共基础设施 |
| P2 | 文档与历史规模增长 | 只做可追溯归档，不回写旧裁决 |

## 7. A8R-HW1 阶段合同

### H0：串行参考收口

在当前进程结束前：

- 可以起草合同、测试和代码，但不得在同一主机启动重型求解器或性能探针；
- 不得影响 PID `51498` 的 CPU、内存、cgroup、affinity、终端或工作树；
- 当前运行结束后先完成第 3.2 节封存。

H0 产物只允许被分类为 `SERIAL-REFERENCE`，科学结论继续由后续独立 Pro 审查决定。

### H1：结果盲硬件合同与硬件清单

任何性能测量前，必须先单独 commit、push：

1. Markdown 结果盲硬件合同；
2. TypeScript/JSON 机器合同；
3. 合同测试；
4. 明确的科学字段输出禁止表；
5. 硬件、安全、正确性、性能和停止门。

随后记录并哈希：

- CPU 型号、socket、物理核、逻辑核、NUMA、cache、ISA；
- `MemTotal`、cgroup 限制、swap 和可用内存；
- 可访问 GPU 的型号、UUID、显存、驱动、计算 API 和占用归属；
- OS、kernel、Node、V8、编译器和关键依赖；
- 本地文件系统和临时目录；
- 可持续内存带宽基线；
- 电源策略、频率和热降频计数器。

硬件清单不得修改无关进程或全局系统设置。

### H2：候选后端与代表性探针

对每类静态可行后端，使用 D54 尺寸和完整力身份数据路径的非科学探针。探针应自适应
达到稳定测量窗口，而不是固定依赖 40 步：

- 至少一次冷启动；
- 预热不少于 32 个完整步骤；
- 每个有效计时窗不少于 15 秒，且不超过 60 秒；
- 至少三次有效重复；
- 另做可覆盖 trace 内存增长的 10 分钟以内 soak 或等价上界证明；
- 只输出时间、CPU、内存、带宽、GPU busy、温度、频率、退出码和哈希；
- 不输出、保存或显示任何科学数值。

候选必须涵盖所有静态可行、可能带来实质净收益的资源类别。未实施的类别必须给出
机器可审计的静态 NO-GO 或 `DEFERRED-UNSAFE-TO-PROBE`，不能只写“复杂”或“预计不快”。

### H2-X：精确执行后端

若候选只改变调度、shard、数据搬运或实现形式，并声称科学算术不变，必须通过：

- 选定 checkpoints 的完整人口原始字节 SHA-256 与串行参考一致；
- 每步力身份摘要和 case scientific payload 规范哈希一致；
- 1 worker、选定 worker 数和人为扰乱完成顺序的聚合 payload 一致；
- 缺失、重复、损坏或中断 shard 时 fail-closed；
- 调度器、PID、计时和资源数据不进入 scientific payload；
- 三个独立环境的限定 smoke 一致。

只有该级可以称为 `EXACT-EXECUTION-EQUIVALENT`。

### H2-N：非逐字节数值后端

GPU、域分解、并行归约、SIMD/native 或其他后端若不能通过 H2-X，不得靠放宽 H2-X
门追认。它必须进入新的 H2-N 数值资格：

- 在任何结果承载运行前冻结新的数值等价合同和阈值；
- 单独验证质量、动量、力、功、稳定性、边界、网格和统计量；
- 至少两套独立实现或一套实现加独立参考；
- 对舍入、归约顺序、确定性和硬件差异给出明确语义；
- 经独立 Pro 接受后才能成为 A8R-HW1 科学后端。

H2-N 的性能 PASS 不等于数值或物理 PASS。

### H3：两个新鲜全量运行

只有选定后端通过 H2-X，或通过 H2-N 并另获独立 Pro 接受，才允许创建
A8R-HW1 主/复跑。

H3 开始前必须：

- 结果前实现提交已经 push；
- 两个干净环境已冻结；
- 所有来源、依赖、后端、编译器、调度和 artifact schema 身份已闭合；
- 规范输出和 shard 路径不存在；
- 资源计划已通过内存和热管理门；
- 当前串行参考的科学输出不得参与后端选择。

## 8. 可实测、可复核的硬件验收标准

### 8.1 基线与指标

在同一主机、同一安全资源窗口中，以当前串行科学路径的受限非科学 probe 作为基线。
当前经历过暂停和外部负载的长时主运行墙钟不得作为基线。

定义：

$$
X=\frac{N_{\mathrm{cells}}N_{\mathrm{steps}}}{10^6T}
$$

为 MLUPS；定义：

$$
S=\frac{T_1}{T_c}
$$

为候选相对串行端到端加速比；对 CPU 并发度 $R$，定义：

$$
E=\frac{S}{R}
$$

为并行效率。

`T_c` 必须包含 worker 启动、数据传输、审计、shard 校验、聚合和规范写入，不得只
计内核。

### 8.2 重复性门

每个有效配置至少三次测量：

- 墙钟变异系数不超过 5%；
- 最慢与最快之比不超过 1.10；
- 环境负载、温度、频率和可用内存可比；
- 任一次出现 OOM、swap 增长、热降频或无关进程干扰，该批次整体无效。

### 8.3 正确性门

- H2-X：全部精确哈希和 fail-closed 门通过；
- H2-N：独立数值合同全部通过；
- 不允许“性能快但结果略有不同”作为未注册的折中；
- 不允许自动 fallback 在同一结果承载运行中切换后端。

### 8.4 性能门

选定配置必须同时满足：

1. 端到端加速比 `S >= 1.50`；
2. 其端到端吞吐不低于全部安全候选最佳值的 95%；
3. 对 CPU 多资源配置，在未证明内存带宽饱和时 `E >= 0.55`；
4. CPU 计算窗内满足下列至少一项：
   - 分配逻辑 CPU 的平均有效占用不低于 70%；
   - 实测内存带宽不低于本机可持续带宽基线的 70%，并且继续增加 CPU 不再带来
     超过 5% 的吞吐提升；
5. GPU 配置若被选择：
   - 计算窗 GPU busy 中位数不低于 60%；
   - 主机到设备传输、同步与序列化合计不超过端到端墙钟的 35%；
   - CPU 喂数不能成为持续单线程瓶颈；
6. 选定配置连续运行代表性 soak 时没有吞吐持续退化超过 10%。

若没有候选同时满足，结论为：

`NO-GO-A8R-HW1-HARDWARE-QUALIFICATION`

不得用“CPU 看起来很忙”或“GPU 被调用过”替代性能门。

### 8.5 内存、安全与热管理

探针和 H3 运行必须在本任务专用 cgroup 或等价隔离中。定义系统保留：

$$
F=\max(4\ \mathrm{GiB},0.25\,\mathrm{MemTotal}).
$$

必须满足：

- `MemAvailable` 始终高于 $F$；
- swap 使用不增长；
- `memory.events` 的 `max`、`oom`、`oom_kill` 不增长；
- 候选峰值内存加 10% 裕量低于专用 cgroup 上限；
- 不触碰无关 CPU/GPU 进程；
- 不发生热降频；若平台只能提供频率代理，持续频率下降超过 15% 则该批次无效；
- 不修改全局 overcommit、drop caches、swap、驱动或电源策略来制造 PASS。

### 8.6 “充分利用”最终门

只有满足以下全部条件，才记录：

`PASS-A8R-HW1-HARDWARE-UTILIZATION`

- 正确性门 PASS；
- 性能门 PASS；
- 内存、安全与热管理 PASS；
- 被选配置在全部安全候选中接近最优；
- 主要瓶颈已被实测识别并高利用；
- 没有一个未评估的可访问资源类别仍有合理概率提供超过 10% 的净提升；
- 全部证据、命令、硬件快照和源身份可复核。

## 9. case shard、聚合和恢复语义

A8R-HW1 应把每个完整 case 写成不可变 shard。shard 必须：

- 只在该 case 从 step 0 完整结束并通过内部有限性、来源和结构门后原子生成；
- 包含 case 定义、scientific identity、execution identity、artifact identity 和
  scientific payload 哈希；
- 使用唯一 case ID、`wx`、规范路径、SHA-256、`realpath` 和 inode 门；
- 不因完成顺序改变规范字节；
- 不允许缺失、重复或损坏 shard 参与聚合。

父聚合器只有在八个唯一 shard 全部闭合后才能生成规范主产物和 sidecar。

shard 允许同一环境在 case 边界恢复未完成矩阵，但不允许：

- 从中间 checkpoint 继续一个尚未完成的科学 case，除非未来合同另行预注册；
- HW1-primary 与 HW1-repeat 互相复用 shard；
- 用当前串行参考的 case 对象或人口状态填补 HW1；
- 根据 shard 的科学值动态改变调度或资源配置。

## 10. 三层身份与结论语义

A8R-HW1 机器产物必须拆分：

### Scientific identity

至少包括：

- 方程、边界、初态、矩阵、mask、相位、窗口、门值；
- 数值内核和浮点/归约语义；
- 力身份、A2 公式和统计定义。

### Execution identity

至少包括：

- scheduler、worker pool、backend、并发度；
- CPU/GPU 设备、驱动、编译器、Node/V8；
- NUMA、affinity、cgroup 和资源计划；
- shard、IPC、传输和失败恢复协议。

### Artifact identity

至少包括：

- schema、字段顺序、数字序列化；
- gzip 参数、sidecar 格式；
- shard 和最终聚合规则。

不得把新 scheduler 排除在 provenance 之外，也不得沿用旧
`implementationTreeSha256` 来伪装新执行路径。

## 13. 停止与 fail-closed 条件

### 当前串行参考

出现以下任一情况时停止普通等待并保全现场：

- PID、启动时间、PGID 或 SID 变化；
- 进程消失或异常信号退出；
- 同一 case 步数倒退或从 step 0 重启；
- 旧工作区出现修改；
- 候选代码、checkpoint 或调试器被加载；
- 八轨迹返回前规范产物异常出现；
- OOM、非有限值、异常栈或 partial 残留且进程已退出。

### H1/H2 候选

出现以下任一情况立即停止候选，不影响无关进程：

- 科学字段被打印、持久化或用于选择；
- H2-X 任一精确哈希不一致；
- H2-N 未有冻结合同却出现非逐字节差异；
- `MemAvailable` 触碰系统保留、swap 增长或 OOM 事件；
- 热降频或无关进程受到本任务操作；
- shard 缺失、重复、损坏或来源不一致；
- backend 在运行中自动 fallback；
- 候选修改既有 A8R 或受保护路径；
- 三次重复不能达到稳定性门；
- 没有配置达到 1.50 端到端加速或 95% 最优吞吐门。

失败证据必须保留，候选结果不能升级为科学结论。

### H3 全量运行

出现以下任一情况，不得自动改参数或重启：

- 结果前来源或硬件身份漂移；
- 主/复跑共享 shard、缓存、checkpoint 或 inode；
- 任一 case 不是从 step 0 开始；
- 聚合器在八 shard 闭合前写规范产物；
- exact 级主/复跑 payload 或 artifact 身份不一致；
- numerical 级超过预注册容差；
- 性能、安全或硬件身份在长时运行中越门。

应保全现场并返回独立 Pro。
