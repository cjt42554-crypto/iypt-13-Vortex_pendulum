## 3. R0 事实裁定

### 3.1 已足以确定的事实

证据足以确定：

- 承载运行的旧 boot 已结束；
- 系统日志达到有序 `System Power Off`；
- 新 boot 中原 npm、shell、Node PID 均不存在；
- 旧工作树仍在 `88c4e9e8...` 且干净；
- 规范 gzip、sidecar 和 `.partial-*` 均不存在；
- artifact asserter 没有执行，因为没有可断言的规范产物；
- 关机前最后实际观察是同一 D54 case 的 `77760/86400 (90%)`；
- 最终窗口没有发现 OOM 记录；
- 没有读取科学 payload。

因此，运行中断的已知外部原因是主机有序关机。该证据不支持把事件分类为数值崩溃、OOM、科学门失败或 A8R 路线 NO-GO。

### 3.2 仍然未知但不阻碍本裁决的事实

下列事实仍未知：

- 最后一次活体观察的精确时间；
- Node 最终收到的具体信号；
- Node 最终退出码；
- 关机前最后一条未显示进度之后实际又完成了多少格子步；
- 进程内已经存在但未序列化的对象字节。

这些未知量不能用系统常识补写。它们不改变“进程已消失且没有规范产物”的关键事实，因此不阻碍路线裁决。

### 3.3 90% 进度的证据上限

`77760/86400 (90%)` 只证明最后一次观察时某条 D54 轨迹达到该进度。它不能证明：

- 该轨迹最终完成；
- 其内部门通过；
- 先前轨迹对象仍可恢复；
- 八轨迹矩阵完成百分比；
- 任何科学趋势或判定；
- 新运行可以从 90% 继续；
- 已消耗计算可以计入未来 H3 完整运行。

该字段只能保留为历史运行现场，不得用于候选选择、性能资格、科学推断或部分结果拼接。

## 4. 为什么不存在可恢复的 A8R 结果

旧运行器只有在 `runBrinkmanMultiresolutionV2P1Qualification()` 返回完整总结果后，才遍历八条 run、写规范 gzip、再写 sidecar。资格入口使用同步 `.map()` 逐条完成轨迹，运行中没有原子 case shard，也没有在完整轨迹结束时写出认证中间产物。

因此：

1. 已完成轨迹只曾存在于已消失的 Node 堆；
2. 第五条或其他进行中的 D54 状态没有规范 checkpoint；
3. 规范 gzip 和 sidecar 不存在；
4. `.partial-*` 也不存在；
5. 旧运行没有可由 artifact asserter 接受的字节对象。

即使底层求解器具有一般 checkpoint API，也不能据此声称本次 A8R 已保存可恢复 checkpoint。R0 证据没有该文件，冻结 A8R 运行也没有启用中间恢复协议。任何事后构造的 checkpoint、heap dump 或手工重建都不是原运行产物。

结论为：

`RECOVERABLE-SCIENTIFIC-BYTES = 0`

`CREDITABLE-COMPLETED-HW1-CASES = 0`

## 6. 是否应从 step 0 重跑旧串行参考

裁决为：**当前路线不重跑完整旧串行参考。**

这不是因为旧实现已被证明错误，而是因为：

1. 用户硬性要求下一次新的结果承载运行充分利用本机可安全使用的硬件；
2. 完整旧串行重跑本身会成为新的长时结果承载运行，却不满足该要求；
3. H1 的性能基线本来就要求同一安全窗口内的受限非科学串行 probe，而不是使用经历暂停和外部负载的长时墙钟；
4. H2-X 可以用冻结科学源的有界非科学 oracle 验证执行等价；
5. H3 的 `HW1-primary` 和 `HW1-repeat` 将从同一结果前实现、两个独立环境、step 0 和新鲜初态完成全部八轨迹；
6. 两次 HW1 全量运行比“旧串行一次 + 新硬件一次”的混合身份更干净；
7. 当前没有旧串行规范科学 payload 可供保留或比较。

因此，旧串行完整重跑既不是 HW2 的必要前置，也不是 H3 的合法替代。

只有未来用户明确撤销“下一次结果承载运行必须充分利用硬件”的要求，并另行裁决，才可重新考虑完整旧串行运行。当前没有该授权。

## 9. WP-HW2 的新入口与串行 oracle

### 9.1 新入口条件

WP-HW2 只有同时满足以下条件才解锁：

1. `PASS-R1I-INTERRUPTED-SERIAL-ATTEMPT-EVIDENCE-SEALED`；
2. `PASS-G1-RESULT-BEFORE-FOUNDATION`；
3. H1 v2 合同、测试和无结果实现全部通过；
4. 当前没有活动结果承载运行；
5. 主机 inventory 完成；
6. 资源窗口满足 H1 内存、swap、OOM、热和无关进程安全门；
7. 工作树干净，`HEAD == origin/main`；
8. 候选和 probe 代码在首次性能观察前已提交并推送。

### 9.2 允许的串行 oracle

H2 允许运行受限的、非科学的冻结源串行 oracle，用于：

- 同窗口性能基线；
- checkpoint 人口字节等价；
- 每步力身份摘要哈希等价；
- 合成或缩短 case scientific payload 的规范哈希等价；
- 1 worker 与多 worker 的调度、排序和 shard 负测试。

该 oracle 必须：

- 绑定旧科学源提交 `88c4e9e8...`；
- 使用 H1 v2 冻结的非科学 profile；
- 不运行完整八轨迹长时矩阵；
- 不输出或持久化科学值；
- 只保存哈希、相同/不同布尔值、计时和资源字段；
- 不被标为 `A8R-V2P1-SERIAL-REFERENCE`；
- 不生成 A8R 规范主 gzip；
- 不形成科学 PASS、INCONCLUSIVE 或 NO-GO。

### 9.3 H2-X 结论上限

在没有完整旧串行产物的情况下，H2-X 可以证明：

`PASS-HW2-EXACT-EXECUTION-EQUIVALENT-TO-FROZEN-SCIENTIFIC-SOURCE-UNDER-QUALIFICATION-ORACLE`

它不能证明：

`BYTE-IDENTICAL-TO-AN-ABSENT-LEGACY-FULL-ARTIFACT`

H2-X 必须至少覆盖：

- 全部八个冻结 case 定义的构造和来源哈希；
- 预分析、分析首步和多个冻结审计步的完整人口字节；
- 每步 force-identity 摘要哈希；
- 缩短但完整的每类 case payload；
- 1 worker、选定 worker 数和完成顺序扰动；
- shard 缺失、重复、损坏、来源漂移和 worker 失败；
- 三个独立轻量环境。

若候选改变科学内核、浮点/归约语义，或任一精确哈希不一致，必须转 H2-N 并触发 PR-2；不得靠“旧完整产物不存在”降低 H2-X 门。
